# BDD: one English feature per behaviour (issue #131)

The `*.pt.feature` twins are gone. Each behaviour has one English `.feature` (the repo's text is English), and `playwright.config.ts` runs the same features in two projects, `bdd-en` and `bdd-pt` (the app in pt-BR), so a report names the language of each run. The steps are registered once, in English, and look for elements by role and by dictionary key in the language of the run (`c.t(key)`, or the dictionary object); `scripts/test/hooks/bdd-guard.test.ts` fails on a new Portuguese twin, a language in a feature's name, a step registered per language, literal UI text in a step (`getByText`, `getByLabel`, `getByRole(..., { name: "…" })`) or an accented letter in a step or feature. Seed data a scenario names uses one name for both languages: the demo's `Write a summary` template has the same title in en and pt-BR, and the approval scenario's session is "BDD approval". The scenarios under `scripts/e2e/bdd/roi/` (parsed only, outside the glob) lost their pt twins too; their parser test still reads Portuguese gherkin, as a parser check. Checked before deleting: each pt feature had the same scenarios and the same step kinds as its English file.
