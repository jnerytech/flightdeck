# Resume what a restart interrupted (issue #150)

- **Daemon.** The restart marks its sessions `error` with the code `daemon_restarted` (it was the Portuguese sentence "daemon reiniciado"; rows an older daemon left are still read). `session.interrupted` lists the sessions of the last 24 hours that are still in `error` from a restart, in the order they were started (a team's coordinator is before its workers), with name, folder, persona, how long they ran and the last request; the host announces it as the feature `resume-offer`, and an old daemon shows nothing.
- **App.** On connect (and on a `host.info` reload) the app asks, filters out what was answered (the offer's memory is in the app's storage, keyed by session and interruption time), and opens one dialog, or resumes by itself when the host's switch is on. A resume is the daemon's own `session.resume` followed by one message, "Continue where you left off."; the original request is never sent again. "Not now" and "Dismiss all" both remember the answer, so neither comes back by itself on a reconnect; the difference is that "Not now" leaves a button on the host's page and "Dismiss all" does not.
- **Not done, on purpose.** The *Queued* state when `maxParallelRuns` is reached: sessions resume through `session.resume`, which has no parallel limit (only cards queue), so a bulk resume can start more at once than a card run would. Resuming a team's coordinator before its workers by the team's order (the daemon order already puts the first-started first, which is the coordinator). The status-bar entry (#118). The smoke with a real daemon restart (the tests mark the sessions the way the restart does). The offer's memory is per app, not per host, so a second app on the same host asks again.
- **After review.** A session with no Claude session id (one caught in `starting`) is not offered: there is nothing to resume. The 24 hours are the only expiry and count inclusively (24 h exactly is offered, 24 h and 1 ms is not). `lastRequest` goes to the app up to 200 characters, never cutting an emoji; it is the person's own text on a host they own. The reason code changed from a Portuguese sentence to `daemon_restarted`: anything that read the old text must also accept the code (the old text is still read here). The query reads the `error` rows through an index on `(status, updated_at)` instead of all sessions, and the feature is one shared constant, `FEATURE_RESUME_OFFER`.
