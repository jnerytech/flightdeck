# The rc/0363 review's minors, closed one by one (issue #222)

OpenCode's review of rc/0363 (v0.36.3) left minors m1 to m11; M1 and m5 were fixed in the rc.
Issue #222 asked for each one to be fixed with a red test or rejected with a reason. m1 and m2
were fixed on main before this audit (287ef2579, 87385669c). The audit of 2026-11-06 found:

- **m3, required check names duplicated by dispatch runs: fixed.** A dispatch run names its
  aggregates `test (ubuntu-latest) (dispatch)` and `test (windows-latest) (dispatch)`, so it
  never publishes a required context. The third required check, `screenshots (prints, axe e e2e)`,
  runs with `if: always()`: a dispatch can publish it only as a real pass or fail of the same
  commit, never as skipped.
- **m4, temp-run on Windows: fixed, two points rejected.** The sweep never throws, takes at most
  one dead folder per process start, and clears the read-only mode before it unlinks.
  `docs/TDD.md` says that a file still held on Windows can keep the folder until the next run.
  A main run on 2026-11-06 still printed "is still held" 1 or 2 times per Windows job.
  - Rejected: a CI assertion on the leftover `fd-run-*` count. CI runners are thrown away after
    each job, so a leftover there never piles up. A dev machine's next run sweeps it.
  - Rejected: `pidAlive` across PID namespaces that share a TEMP. No container here shares a TEMP
    with the host or with another container.
- **m6, tests that read class names or source text: fixed, one part rejected.** The class and CSS
  tests (`abas-largura`, `layout-overflow`) are labelled as cheap guards, not proofs. The layout
  is measured in a real browser by the e2e `layout` journey: the breadcrumb's widths, a floor for
  the current crumb, and the tabs (`scripts/e2e/journeys.ts`).
  - Rejected: replacing the `ci.yml` text tests. A workflow runs only on GitHub, so its tests can
    only read its text. CI's own runs are what prove it.
- **m7, tab badges by colour alone: fixed.** Each badge has its own glyph (`CircleAlert` for
  needs-you, `LoaderCircle` for running, `Circle` for unread) besides its colour, as #172 asked
  (WCAG 1.4.1).
- **m8, the slot's nested test: fixed.**
  - The nested test runs `process.execPath`, not `echo`.
  - The child gets `FLIGHTDECK_SLOT_LOCK`.
  - The log line has its line breaks replaced, and its `NOSONAR` names what reaches it.
- **m9, 8.3 tests: fixed.** Both Windows tests skip when the volume makes no 8.3 names
  (`volumeHas83Names()`).
- **m10, the in-process PR runner: fixed, two points rejected.**
  - The in-process `run` now records each call's stdin (`inputs()`), and a test checks that the
    GitHub review threads query arrives there.
  - `gh` got the twin of `az`'s real-spawn test, so both providers still start their CLI through
    `runCommand` when no runner is given.
  - Rejected: the fake's process reading stdin. A caller that leaves the pipe open would hang it,
    which is the kind of slowness the in-process runner removed (#246). That process records "".
  - Rejected: `delayMs` and `holdPipesMs` in process. They describe a process, and the tests that
    need them still start one.
- **m11, small things: one fixed, one split off.** The "How far from the end" comment sits over
  `END_SLACK`. The restore at mount (`SessionView.tsx`, `saved.top` set before late content lays
  out, so a clamped `scrollTop` can overwrite the saved place) is a possible UI bug that needs a
  reproduction with late-growing content. It moves to #515, owned by the UI.
