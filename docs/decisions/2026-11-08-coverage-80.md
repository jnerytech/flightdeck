# The coverage gate is 80%, and flaky or slow tests are deleted (issue #1002)

**Decision (the person, 2026-11-08):** the coverage gate drops from 100% to 80% of each source
file's lines and functions, everywhere. From now on, tests focus on business logic and the
important flows. The person also asked to delete flaky and too-slow tests ("excluir testes
intermitentes / lentos demais", #1003).

**Why:** the 100% gate made sessions write tests only to reach a line. Timing-only lines also
failed whole runs with no failing test: on v0.37.12, `board.ts:1568` blocked the bump PR twice
(#996). Release speed matters more than the last 20%.

**What changes:**
- **One threshold for every gate:** `COVERAGE_GATE = 80` in `scripts/lib/coverage-check.ts`. A
  file is below the gate when it runs less than 80% of its lines, or of its functions; a file
  with nothing to run never is.
  - `bunfig.toml`'s `coverageThreshold` is 0.8 for lines and functions.
  - `check-coverage.ts` and the merged shard gate (`shard-gate.ts`) use `checkCoverage`.
  - `test:related`'s changed-file and new-import gates (`checkChanged`) and its whole-suite
    verdict use it too. A file at the gate passes, whatever lines it leaves uncovered.
  - The fast-coverage ratchet keeps each file the fast tiers cover at 80% at 80%.
  - SonarCloud's quality gate already asked for 80% on new code.
- **A flaky test is deleted, never skipped.** When it is the only check of a business flow, it
  is replaced by a fast deterministic test. #1003 (fd-qa) removes the `// unstable:` skips still
  in the repository. Until then, the hook, the TDD audit and the unstable-skip ratchet still check
  their notes.
- **Too slow on CI:** a test over 5 s, a test file over 60 s, or an e2e journey over 90 s.
- **Unchanged:** the TDD order (a red `test(x)` commit before `feat`/`fix`), the security gate,
  and every rule about touching nothing real.

**Where:** `CLAUDE.md`, `docs/TDD.md`, `.claude/rules/tests.md`, the CI step name
"Testes (cobertura 80%, 3 shards)", and the tests that pin the gate (`coverage-check.test.ts`
reads the threshold in `bunfig.toml`).
