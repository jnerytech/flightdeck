# The feeds from a shell: flightdeckd logs, releases, alert and activity (issue #3736)

The CLI-first slice of #3423 for four read-only requests the app already makes: `logs.tail`, `releases.list`,
`alert.list` and `activity.since`.

## Decision

- **The verbs.** `logs tail [--lines <1-500>]`, `releases list [--limit <1-20>]`, `alert list <project>` and
  `activity since <iso-time> [--limit <1-50>]`. Each calls the request the screen calls, on this machine or on a paired
  host with `--host`, and takes `--json`. Exit codes: 0 done, 1 refused, 2 no daemon.
- **The ranges are the daemon's.** A value outside the range the request accepts is refused by the parser with the
  range in the text, before any connection. `--lines` is `review add`'s flag too: it means a count of log lines on
  `logs` and a line range of the diff on `review`. `--limit` keeps its 1 to 1000 elsewhere.
- **A time is any ISO date and time with a zone.** The request takes strict UTC text, so the parser turns
  `2026-11-20T02:00:00+02:00` into `2026-11-20T00:00:00.000Z`. A date with no time, a word or a number of seconds is
  refused, because a bare date would be read in the zone of the machine.
- **A project is its id or its name**, as in `memory` and `knowledge`. An unknown name is refused with the names that exist,
  and nothing is asked of the daemon.
- **`--json` keeps every key.** A key a host leaves out is `null`, so a script reads the same shape from an older host.
  `alert list --json` prints the alerts and the sources that could not be read.
- **Daemon text is data.** Titles, names and log lines are printed with their control characters replaced.
- **`logs tail` is high-risk from a session's shell.** The daemon's log holds paths and hosts, and whatever its redaction
  missed. The app shows it to the person, who chose to look; a session reading it would read what it was never given.
  `releases list`, `alert list` and `activity since` show what the app shows without a choice, so they stay ordinary.

## Discarded

- **A `--since` flag on `logs tail`.** The request takes a count; filtering the lines by time would mean reading the whole file.
- **Reading a bare date.** It would silently depend on the zone of the machine that typed it.

## Consequences

- `docs/cli-parity.json` marks the four requests as reached by `logs`, `releases`, `alert` and `activity`; the number of
  requests with no command falls by four.
- `runtime.models` and `costs.sessions` are not part of this slice.
